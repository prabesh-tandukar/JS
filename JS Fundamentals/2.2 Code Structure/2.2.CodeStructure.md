# Code Structure

Now we will look into the building blocks of code.

## Statements

Statments are syntax constructs and commands that perform actions.
For example, _alert('hello')_, is a statements which shows the message 'hello'.
We can have as many statements as we want in our code and separate each statement with a semicolon. Best pratice: writing each statement on there own line for readability.
Eg:

```javascript
alert("Hello");
alert("World");
```

## Semicolons

A semicolon can be omitted in most cases when a line break exists.

```
alert("Hello")
alert("World")
```

This will work because JavaScript interprets the line break as an "implicit" semicolon. This is called an automatic semicolon insertion.

**In most cases, a newline implies a semicolon. But "in most cases" does not mean "always"**

There are cases when a newline does not mean a semicolon. For eg:

```
alert(3 +
1
+ 2);
```

The code will output "6" because JS does not insert semicolons here. It is intuitively obvious that if the line ends with a plus "+", then it is an "incomplete expression", so a semicolon there would be incorrect. And in this case that works as intended.

**But there are situations where JavaSciprt "fails" to assume a semicolon where it is really needed**

Error which occur in such cases are quite hard to find and fix.

##### An example of error

```javascript
alert("Hello");
[1, 2].forEach(alert);
```

The result of running this code is it shows Hello, then 1 and 2 each in that order.

Now, if we remove semicolon after the alert:

```
alert("Hello")
[1,2].forEach(alert);
```

The difference is only one character - the semicolon at the end of alert.

If we run this code, only the first "Hello" shows. Then the numbers wont show but we will receive an error.

That's because JavaScript does not assume a semicolon before square brackets [...]. So, the code in the last example is treated as a single statement.

Here's how the engine sees it:

```javascript
alert("Hello")[(1, 2)].forEach(alert);
```

Such merging in this case is wron and we need to put a semicolon after the alert to make it work correctly.

This can happen in other situations as well.

So, we will put semicolon between statments everytime even if they are separated by newlines.

## Comments

We can put comments in our code which is not executed and ignored by the engine. We can write comment to describe the code and any other reason.

**One line comments start with two forward slash characters //**

```javascript
//This comment occupies a line of its own
alert("hello");
alert("world"); // This comment follows the statment
```

Multiline comments start with forward slash and and asterisk /\* and end with asterisk and forward slash \*/

```javascript
/* An example with two messages.
This is a multiline comment.
*/
alert("Hello");
alert("World");
```
